Bestar 系统 Windows 公网直连历史备选教程

适用场景：系统部署在公司局域网内的一台 Windows 11 或 Windows Server 主机上，外部人员需要通过公司公网 IP 或公司持有的子域名访问。

当前推荐方案：公司公网 IP 不稳定时，请使用 Cloudflare Named Tunnel 中英双语操作手册。 Named Tunnel 使用出站连接，不需要路由器开放 80/443 入站转发。本页以下 Caddy + 公网 IP 内容仅作为经过单独安全审批后的历史备选方案，不是当前默认部署路线。
历史直连方案的安全底线：只有在明确批准使用本页方案时，才允许将公网 80/443 转发到 nginx/Caddy。任何情况下都不要把 PostgreSQL、Redis、API 4000、Web 3000 或 Docker 直接暴露到公网。

1. 当前项目端口关系

组件 项目内端口 公网是否开放 说明
Docker nginx HTTP_PORT，默认宿主机 80 可以 统一入口，负责 / 到 Web、/api 到 API。
Web 容器内 3000 不开放 只给 nginx 容器访问。
API 容器内 4000 不开放 只通过 /api 访问。
PostgreSQL 宿主机 15432 不开放 只允许本机或受控内网维护。
Redis 宿主机 16379 不开放 绝不能暴露公网。

2. 外网访问的前置条件

公司公网 IP

需要确认公司网络是否有公网 IPv4。打开路由器 WAN 页面查看 WAN IP，再用外部网站查询出口 IP，两者一致才通常可以端口转发。

如果 WAN IP 是 10.x.x.x、100.64.x.x、172.16-31.x.x、192.168.x.x，大概率是 CGNAT 或上级路由，外部不能直接访问。

固定服务器内网 IP

部署机器必须固定内网 IP，例如 192.168.1.50。推荐在路由器 DHCP Reservation 里按 MAC 地址绑定，不推荐手写一个可能冲突的静态 IP。

公司域名管理权限

需要能进入域名 DNS 控制台，新增子域名记录，例如 unloading.company.com 或 warehouse.company.com。

HTTPS 证书

真实公网访问必须使用 HTTPS，特别是登录账号密码和 JWT Token。推荐用 Caddy 自动申请 Let's Encrypt 证书。

3. 推荐 Windows 生产方案：子域名 + HTTPS + Caddy + Docker nginx

推荐结构如下：

Internet
  -> https://unloading.company.com
  -> 公司公网 IP
  -> 路由器端口转发 TCP 80/443
  -> Windows 部署主机 Caddy
  -> http://127.0.0.1:8080
  -> Docker nginx
  -> Web / API
本方案让 Caddy 监听公网 80/443 并自动维护 HTTPS 证书；本项目 Docker nginx 改为只监听宿主机 8080，避免端口冲突。

4. Windows 部署主机配置

4.1 固定 Windows 主机内网 IP

先确认部署主机在公司局域网内的 IP，例如 192.168.1.50。推荐在路由器里做 DHCP Reservation，让这台 Windows 主机每次都拿到同一个内网 IP。

  1. 在 Windows 上打开 PowerShell。
  2. 运行 ipconfig，找到正在使用的 Ethernet 或 Wi-Fi 网卡。
  3. 记录 IPv4 Address，例如 192.168.1.50。
  4. 记录 Physical Address，也就是 MAC 地址。
  5. 登录公司路由器，进入 DHCP Reservation / Address Reservation。
  6. 把这台机器的 MAC 地址绑定到固定 IP，例如 192.168.1.50。
  7. 重启网络或重启电脑后，再运行 ipconfig 确认 IP 没变。
ipconfig

4.2 准备 Windows 项目目录

建议项目固定放在短路径，不要放 OneDrive、桌面同步目录或中文路径下。

mkdir C:\bestar-unloading
cd C:\bestar-unloading

把项目代码放入 C:\bestar-unloading 后，确认这些文件存在：

dir infra\docker\compose.local.yml
dir infra\nginx\nginx.conf
dir .env.example
dir storage

4.3 修改项目 .env

在项目根目录创建并编辑 .env。假设子域名是 unloading.company.com，Windows 主机内网 IP 是 192.168.1.50，推荐值如下：

copy .env.example .env
notepad .env
HTTP_PORT=8080

# Web browser uses same-origin /api through reverse proxy.
NEXT_PUBLIC_API_BASE_URL=/api
WEB_SERVER_API_BASE_URL=http://api:4000/api
WEB_API_PROXY_BASE_URL=http://api:4000/api

# Add public domain and LAN URLs. Replace examples with real values.
CORS_ORIGINS=https://unloading.company.com,http://192.168.1.50,http://localhost,http://127.0.0.1

TZ=America/Edmonton
OPERATIONAL_TIME_ZONE=America/Edmonton
NEXT_PUBLIC_OPERATIONAL_TIME_ZONE=America/Edmonton

# Must be changed before production.
POSTGRES_PASSWORD=replace-with-strong-password
JWT_SECRET=replace-with-long-random-secret

4.4 启动或重启 Docker 全栈

确保 Docker Desktop 已启动，并且使用 Linux containers。然后在 PowerShell 中运行：

cd C:\bestar-unloading
docker compose -f infra/docker/compose.local.yml up -d --build
docker compose -f infra/docker/compose.local.yml ps
curl.exe http://127.0.0.1:8080/api/health
curl.exe -I http://127.0.0.1:8080/

如果 curl.exe http://127.0.0.1:8080/api/health 正常返回，说明本项目 Docker nginx 已经在 Windows 主机本机可访问。

4.5 安装 Caddy 到 Windows

Caddy 用来监听公网 80/443，自动申请 HTTPS 证书，然后转发到本项目的 127.0.0.1:8080。

  1. 打开 https://caddyserver.com/download。
  2. 选择 Windows amd64 版本下载。
  3. 创建目录 C:\caddy。
  4. 把下载得到的 caddy.exe 放到 C:\caddy\caddy.exe。
mkdir C:\caddy
C:\caddy\caddy.exe version

4.6 创建 Windows Caddyfile

创建文件 C:\caddy\Caddyfile，替换成公司真实子域名：

unloading.company.com {
  encode gzip

  reverse_proxy 127.0.0.1:8080 {
    header_up Host {host}
    header_up X-Real-IP {remote_host}
    header_up X-Forwarded-For {remote_host}
    header_up X-Forwarded-Proto {scheme}
  }
}

用 PowerShell 验证配置：

C:\caddy\caddy.exe validate --config C:\caddy\Caddyfile

4.7 先用前台模式测试 Caddy

第一次不要直接装服务，先在 PowerShell 里前台运行，方便看到证书申请和反向代理错误。

C:\caddy\caddy.exe run --config C:\caddy\Caddyfile

如果这里提示无法绑定 80 或 443，说明这些端口已经被 IIS、其他 nginx、其他代理或 Docker 直接占用了。需要先停掉占用端口的程序。

netstat -ano | findstr ":80"
netstat -ano | findstr ":443"

测试通过后，在该窗口按 Ctrl+C 停止 Caddy。

4.8 安装 Caddy 为 Windows Service

用管理员权限打开 PowerShell，然后运行：

C:\caddy\caddy.exe service install --config C:\caddy\Caddyfile
C:\caddy\caddy.exe service start
Get-Service caddy

以后修改 C:\caddy\Caddyfile 后，使用：

C:\caddy\caddy.exe validate --config C:\caddy\Caddyfile
C:\caddy\caddy.exe reload --config C:\caddy\Caddyfile

5. 路由器端口转发

在公司路由器或防火墙上添加端口转发。假设部署主机内网 IP 是 192.168.1.50：

外部端口 协议 转发到内网 IP 内网端口 用途
80 TCP 192.168.1.50 80 Let's Encrypt HTTP 验证和自动跳转 HTTPS。
443 TCP 192.168.1.50 443 正式 HTTPS 访问。
不要转发 3000、4000、15432、16379。如果路由器有 UPnP，建议关闭，避免服务被自动暴露。

6. Windows 防火墙

  1. 打开 Windows Security。
  2. 进入 Firewall & network protection。
  3. 确认公司网络配置为 Private network。
  4. 新增 Inbound Rule，允许 TCP 80 和 443。
  5. 不要允许公网访问 PostgreSQL、Redis、Web 3000、API 4000。

也可以使用管理员 PowerShell 创建规则：

New-NetFirewallRule -DisplayName "Bestar HTTPS 443" -Direction Inbound -Protocol TCP -LocalPort 443 -Action Allow
New-NetFirewallRule -DisplayName "Bestar HTTP 80" -Direction Inbound -Protocol TCP -LocalPort 80 -Action Allow

确认规则存在：

Get-NetFirewallRule -DisplayName "Bestar HTTPS 443"
Get-NetFirewallRule -DisplayName "Bestar HTTP 80"

7. 公司域名解析到公网 IP

7.1 固定公网 IP

进入域名 DNS 控制台，新增 A 记录：

Type Name / Host Value TTL
A unloading 公司公网 IPv4，例如 203.0.113.10 300 或 600

生效后访问：https://unloading.company.com

7.2 动态公网 IP

如果公司公网 IP 会变化，有两种选择：

  1. 向 ISP 申请固定公网 IP，这是最稳的生产方式。
  2. 使用 DDNS，让路由器或部署主机自动更新域名记录。可用 CNAME 指向 DDNS 域名，例如 unloading.company.com CNAME company-warehouse.ddns.example。

7.3 有 IPv6 的情况

如果公司有公网 IPv6，可以添加 AAAA 记录。但必须确认防火墙允许且部署主机 IPv6 地址稳定。没有经验时，先只用 IPv4 A 记录。

8. 验证步骤

8.1 Windows 本机验证

curl.exe http://127.0.0.1:8080/api/health
curl.exe -I http://127.0.0.1:8080/
curl.exe -I https://unloading.company.com/

8.2 DNS 验证

nslookup unloading.company.com

8.3 公司内网其他电脑验证

  1. 在另一台公司内网电脑打开 https://unloading.company.com。
  2. 如果打不开，但外网能打开，通常是路由器不支持 NAT loopback，需要公司内网 DNS 把该子域名解析到 Windows 主机内网 IP。
  3. 也可以临时访问 http://192.168.1.50:8080 判断 Docker nginx 是否正常。

8.4 外网验证

  1. 用手机关闭 Wi-Fi，使用蜂窝网络。
  2. 打开 https://unloading.company.com。
  3. 登录管理员账号。
  4. 打开 https://unloading.company.com/api/health，确认 API 可达。
  5. 测试导入、下载报告、下载面单，确认浏览器没有混用 127.0.0.1、:3000 或 :4000。

9. 临时公网 IP 直连测试

如果只是临时测试，不配置域名和 HTTPS，可以把路由器 TCP 80 转发到部署主机 TCP 80，并让项目 .env 保持 HTTP_PORT=80。

cd C:\bestar-unloading
docker compose -f infra/docker/compose.local.yml up -d --build
curl.exe http://127.0.0.1/api/health

外部访问：

http://公司公网IP/
这种方式没有 HTTPS，不适合账号登录和生产使用。只可用于短时间网络连通性验证。

9.1 Windows 开机自启动建议

生产环境应保证 Windows 重启后 Docker Desktop、Bestar Docker stack 和 Caddy 都能恢复。

  1. Caddy 使用上面的 Windows Service 安装方式，随系统启动。
  2. Docker Desktop 设置为开机启动。
  3. Docker Compose 中服务已配置 restart: unless-stopped，Docker Desktop 启动后容器会自动恢复。
  4. 重启 Windows 后运行 docker compose -f infra/docker/compose.local.yml ps 和 curl.exe https://unloading.company.com/api/health 检查。

10. 常见问题

现象 原因 处理
外网打不开，但内网能打开 路由器端口转发、运营商 CGNAT、公司防火墙未放行。 检查 WAN IP 是否为公网 IP；检查 TCP 80/443 转发；用手机蜂窝网络测试。
域名解析后仍打开旧地址 DNS TTL 缓存未过期。 等待 TTL，或本机刷新 DNS 缓存；用 nslookup 验证。
HTTPS 证书申请失败 80 端口没有转发到 Caddy，或 DNS 没指到当前公网 IP。 先确保 http://unloading.company.com 能到 Caddy，再重载 Caddy。
页面能打开，API 报错 CORS_ORIGINS 未加入域名，或前端仍使用旧 API 地址。 设置 NEXT_PUBLIC_API_BASE_URL=/api，把 https://unloading.company.com 加入 CORS_ORIGINS，重建容器。
公司内网用域名打不开，外网能打开 路由器不支持 NAT loopback。 在公司 DNS 或路由器里做 split DNS：unloading.company.com 内网解析到服务器 LAN IP。

11. 生产安全检查清单

  • 公网只开放 TCP 80 和 443。
  • 没有开放 3000、4000、15432、16379。
  • 域名使用 HTTPS，浏览器地址栏显示有效证书。
  • POSTGRES_PASSWORD、JWT_SECRET 已替换为生产强密码。
  • 管理员账号已设置强密码，默认测试账号已删除或禁用。
  • 已配置 PostgreSQL 和 storage/ 备份。
  • 外网访问日志可查看，异常登录有审计记录。
  • 手机蜂窝网络能打开页面、登录、下载报告和面单。
  • 公司内网电脑使用域名访问时不会跳到 127.0.0.1、:3000 或 :4000。

13. HTTPS证书

HTTPS 证书有三种选择：

  1. 推荐：免费证书，不需要购买用 Let’s Encrypt 免费证书即可。如果按我文档里的 Caddy 方案，只要：
    • - 域名解析到公司公网 IP
    • - 路由器转发 80 和 443
    • - Caddy 正常运行

      • Caddy 会自动申请、安装、续期证书。生产环境推荐这个。

  2. 自己创建自签名证书可以自己创建，但不推荐给正式使用。问题是浏览器、手机、扫码 App 会提示“不安全”或直接拒绝，除非你在每台设备上手动安装并信任公司根证书。维护成本高，容易出问题。
  3. 购买商业证书可以购买，但通常没必要。只有在公司政策要求、需要特定品牌证书、或不能使用 Let’s Encrypt 自动续期时才考虑。

历史方案结论：只有在固定公网 IP、入站端口和相关安全风险均已单独批准时，才考虑 Caddy + Let’s Encrypt。当前动态 IP 公网访问应优先采用不需要入站端口转发的 Cloudflare Named Tunnel。
